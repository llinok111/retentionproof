# 保持率校准：把调度器的预测和真实回忆对一遍

[Handbook](README.md) · [相关页面](PRACTICE.md) · [测试约定](TESTING.md)

精通之路的复习调度建立在一条可测量的判断上：`SpacedRepetitionScheduler.retrievability()`
认为某个知识点"现在还有多少概率能想起来"，`schedule_review()` 再按这个判断算下次到期时间。
这条判断如果偏乐观，间隔就会排得太长；偏悲观，复习就会白做。

上游代码自己写在注释里：默认模型是"按知识类型给冷启动先验的指数遗忘，**不是校准过的 FSRS**"。
而 `deeptutor/services/practice/analytics.py` 只统计每天的做题数、错题数和复习数——
**没有任何地方回答"这个预测准不准"**。本页描述的 `deeptutor/learning/calibration.py`
就是补这一格：把每个预测和它后面的真实结果配对，给出可复算、可反驳的数字。

## 跑一次

```bash
# 已导出的 LearningProgress 快照（mastery_paths.state_json 的内容，或 {"progress": {...}}）
deeptutor learning calibration progress.json

# 直接从学习空间读某个路径
deeptutor learning calibration --store-root ~/.deeptutor/workspace/learning --path <path_id>

# 机器可读 + 落盘
deeptutor learning calibration progress.json --json -o report.json
```

退出码是契约：`0` 没有 P0/P1 发现，`1` 有，`2` 是用法或读取错误。
报告不调用模型、不访问网络、不启动服务；同一份快照永远渲染同一份报告
（bootstrap 固定种子）。

## 怎么算的

1. **事件配对。** 按聚合里 `learning_evidence` 的**追加顺序**逐条复算（与
   `replay()` 一致：延迟到达的跨面写入保留源时间戳，但不重排历史）。
   每条事件取**它发生之前的那个状态**，调 `retrievability()` 得到预测值；
   再用 `_resolved_quality()` 读出这条事件的结果强度，`quality >= 0.5` 记为一次成功回忆。
2. **应用同一条转移。** 预测完就把事件交给真实的 `schedule_review()` 推进，
   所以整段轨迹与 App 当初跑过的完全一致；没有第二份数学实现。
3. **稳定性比值。** 保持率是指数的：`exp(-t/(k·S)) == exp(-t/S) ** (1/k)`。
   于是"真稳定性 / 模型稳定性 = k"可以被极大似然估计出来——对每个候选 k
   算对数损失，取最小。`k = 1` 是模型正确，`0.5` 是学员忘得比模型以为的快一倍。
   置信区间用**按知识点整块重抽**的 bootstrap：同一知识点的多次作答共享同一个稳定性，
   按事件独立重抽会假装证据比实际多。
4. **迟到不算校准错误。** 学员拖到逾期三天才答，成功率当然低于目标——
   但模型当时也已经把预测调低了。比值估计不重建"经过了多少天"，
   所以拖堂本身不会把它推向"模型偏乐观"。

## 指标

| 指标 | 含义 | 读法 |
| --- | --- | --- |
| `bias` | 预测均值 − 实测成功率 | 正数=过度自信，负数=过度悲观 |
| `Brier` / `skill_score` | 平方误差 / 相对基准率的改进 | `skill_score ≤ 0` 说明预测还不如"每天按平均正确率猜" |
| `ECE` / `MCE` | 可靠性分箱的加权平均偏差 / 最大偏差 | MCE 只读样本占比 ≥5%（且 ≥5 条）的分箱，避免两条样本定调 |
| `AUC` | 预测值把"记住了"排在"忘了"前面的能力 | 平均准、逐条没用时会很低；全同值时为 0.5 |
| `at_target` | 只保留真正"隔开时间"的复习（同一次会话里的重复练习不算） | 目标承诺的对象就是这批事件 |
| `retention_scale.scale` | 真稳定性 / 模型稳定性 | `1.00` 正确；`0.50` 间隔应缩短一半 |
| `mean_lateness_days` | 作答时刻与到期时刻的平均差 | 解释"为什么实测低于目标"的第一嫌疑人 |
| `recommended_target` | 让目标真正成立的 `desired_retention`（`target ** scale`） | 超出 0.7–0.99 时标注 `clamped` |

## 发现码与阈值

| 码 | 级别 | 触发条件 |
| --- | --- | --- |
| `calibration.insufficient_evidence` | P3 | 配对事件 < 20 条，只报数不下结论 |
| `calibration.overconfident` / `.underconfident` | P1 | 偏差的 95% Wilson 区间整体越过 ±10%（按类型为 ±12%，且该类型 ≥15 条） |
| `calibration.stability_mismatch` | P1 | 稳定性比值的 95% 区间整体离开 0.85–1.15；区间含着 1.0 就不算成立 |
| `calibration.stability_matches` | P3 | 比值区间与上面相反（明确写"没发现不校准"，避免"没报=通过"的误读） |
| `calibration.non_discriminating` | P2 | ≥50 条且 AUC < 0.6 |
| `calibration.state_divergence` | P2 | 存储的 `review_count` / `lapse_count` 与证据复算不一致 |

`state_divergence` 故意只比计数器：`stability`、`difficulty`、`interval_index` 依赖
状态创建时刻这个锚点，复算从第一条证据开始，差一点是正常的；计数器不一样，
只可能是写入丢失、重复提交或换目标后的重排。

## 实测

`tools/calib-bench/simulate.py` 用 `deeptutor/learning/tests/_simulate.py` 造出真值已知的学员：
答对概率 `exp(-经过天数 / (ratio · 模型稳定性))`，`ratio` 就是审计要还原的那个数。
20 seeds/格、目标 0.9、作答迟到 0–1.5 天：

| 事件数 | 真实比值 | 估计中位数 | 区间覆盖 | 报 P1 的比例 |
| --- | --- | --- | --- | --- |
| 224 | 0.3 | 0.31 | 90% | 100% |
| 224 | 0.5 | 0.49 | 80% | 90% |
| 224 | 0.8 | 0.78 | 90% | 15% |
| 224 | 1.0 | 0.98 | 80% | 10% |
| 224 | 2.0 | 1.69 | 90% | 50% |
| 224 | 3.0 | 2.75 | 90% | 100% |
| 500 | 0.5 | 0.48 | 90% | 100% |
| 500 | 1.0 | 1.01 | 85% | 5% |
| 500 | 2.0 | 2.01 | 95% | 85% |
| 500 | 3.0 | 3.29 | 95% | 100% |

**误报**：`ratio = 1.0` 的两格 40 次里报出 P1 3 次（7.5%，名义 95% 区间）；
条数越多越少（500 事件 5%）。

**闭环**：把 `recommended_target` 直接设回去重跑，量"到期时刻"的真实保持率
（不是作答时刻——迟到是学员带来的，目标承诺的是到期那一刻）：

| 真实比值 | 到期保持率（前） | 建议目标 | 到期保持率（后） | 作答时刻保持率（后） |
| --- | --- | --- | --- | --- |
| 0.3 | 74% | 0.97 | 91% | 68% |
| 0.5 | 82% | 0.95 | 90% | 74% |
| 1.0 | 90% | 0.90 | 90% | 84% |
| 2.0 | 95% | 0.81 | 90% | 88% |
| 3.0 | 97% | 0.73 | 90% | 89% |

五档都在 ±1 个百分点内回到 0.9：说明建议值不是修辞，改完就兑现。

**成本**：单核 Windows，224 条事件约 190 ms，500 条约 400 ms（bootstrap 200 次重抽）。
原始数据落在 `tools/calib-bench/last-run.json`，任何一次重跑都会覆盖它。

## 怎么读结论

- `scale < 1`（模型偏乐观）：间隔按 `scale` 缩短；等式换算到目标就是
  `target ** scale` 更高。报告同时给出这两个数，改哪个都行。
- `scale > 1`（模型偏悲观）：间隔可以拉长，复习次数下降。
- `mean_lateness_days` 大但比值仍接近 1：问题不在模型，在"到期了没人答"。
  这时候该改提醒或排期，而不是改模型。
- `state_divergence` 出现：先查写入路径（跨面评估、并发、迁移），
  再谈模型。预测本身是复算出来的，不依赖存储状态。

## 已知限制

- **需要真实证据量。** 20 条以下只报数；224 条时对"偏乐观"方向已经够用
  （0.5 → 90% 检出），对"偏悲观"方向要到 500 条左右才稳（2.0 → 85%）。
  这是信息量问题，不是调参能绕过的：`p` 越接近 1，一次失败提供的信息越多。
- **只覆盖有证据的知识点。** 只有测验/评估写入的知识点才有配对事件；
  学习者在聊天里"感觉学会了"不进入这里。
- **不改引擎。** `scheduler.py`、`service.py`、`models.py` 逐字节未动；
  本层只读快照。要不要写回目标由人决定（`set_desired_retention` 已有）。
- **不判断教学好坏。** 它只说"预测和结果差多少"，不说为什么差。
